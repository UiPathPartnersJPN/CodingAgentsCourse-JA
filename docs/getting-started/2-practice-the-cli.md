# 2. CLI を使ってみる

!!! tip "このレッスンの進め方"

    1. CLI で何ができるのかを見て回ります。
    2. `docsai` でドキュメントに質問します。
    3. プラットフォームから情報を読み取ります。
    4. ターミナルから離れずにフィードバックを送ります。

## ゴール

`uip` CLI で構築を始める前に、**CLI そのものに慣れておきましょう。** 読み取り専用のコマンドをいくつか実行し、コマンドラインからドキュメントを検索し、フィードバックの送り方を覚えます。

こうしておくと、エージェントが CLI を操作し始めたときにも「見慣れた」感覚で追えるようになります。**エージェントが何をしているのか分かる**ことは、生成物をレビューするうえで効いてきます。

## ツールとスキル

コア CLI の隣には、2 つの拡張の仕組みがあります。

| 仕組み | 役割 |
|---|---|
| **ツール（Tools）** | UiPath のサービス（Orchestrator、Integration Service など）とやり取りする**コマンドを追加**する |
| **スキル（Skills）** | それらのコマンドの**使い方をコーディングエージェントに教える** |

どちらも CLI からインストールでき、頻繁に更新されます。こまめに最新版を取得してください。

```bash
uip tools update
uip skills update
```

## 手順

### 1. 使えるものを確認する

まずは組み込みのヘルプと、インストール済みのツールから始めます。

```bash
uip --help
uip tools list --output table
```

!!! tip "`--help` は最も信頼できる情報源です"
    あとでエージェントが行き詰まったときも、**`--help` を実行して出力を読ませるのが最短の解決策**になります。

    ```text
    uip or processes create --help を実行して、使えるオプションを確認してから進めてください。
    ```

### 2. docsai でドキュメントに質問する

`docsai` は、ドキュメントに基づいて UiPath に関する質問にターミナルから答えてくれます。

```bash
uip docsai --help
uip docsai ask "UiPath CLI で Orchestrator のフォルダーを一覧表示するにはどうすればよいですか？"
```

!!! note "初回は少し時間がかかります"
    `docsai` ツールが未インストールの場合、**初回実行時に自動でインストールされます。** 数分かかることがあります。

{% if course_env == "staging" %}
!!! warning "この環境では出典リンクを開けません"
    検証環境（staging）では、`docsai` が返す出典 URL が社内向けのドキュメントサイトを指すため、**ブラウザーで開けません。** 回答の内容自体は参考になります。

    リンク先を確認したい場合は、[docs.uipath.com](https://docs.uipath.com) で同じ内容を検索してください。
{% endif %}

### 3. プラットフォームから読み取る

docsai の回答でおそらく次のコマンドが提示されたはずです。実際に実行してみましょう。

```bash
uip or folders list --output table
```

ほかにも、読み取り専用で安全に試せるコマンドがあります。

```bash
# テナント一覧
uip login tenant list --output table

# パッケージ一覧
uip or packages list --output table

# 利用できる LLM モデル（第2部 レッスン1 で使います）
uip codedagent list-models
```

!!! tip "エージェントに運転してもらう"
    これらのコマンドを暗記する必要はほとんどありません。スキルの狙いは、たとえば「**公開先にできるフォルダーを一覧表示して**」のように結果を伝えるだけで、エージェントが適切な `uip` コマンドを選んでくれる点にあります。

    とはいえ、自分でいくつか実行してみると勘所がつかめます。また、**繰り返し実行するケースでは、毎回エージェントに頼むよりスクリプト化したコマンドのほうがトークンの節約になります。**

### 4. 出力形式を使い分ける

ほとんどのコマンドは `--output` で形式を選べます。

```bash
uip or folders list --output table   # 人が読む
uip or folders list --output json    # スクリプトやエージェントが読む
```

`--output-filter` で必要な項目だけ取り出すこともできます。

```bash
uip or folders list --output json --output-filter "[*].{Name:Name,Key:Key}"
```

!!! tip "エージェントに渡すときは JSON が有利です"
    表形式は長い値が省略されます（`...` で切られます）。**エージェントに読ませる・スクリプトで扱う場合は `--output json` を使ってください。**

### 5. フィードバックを送る

コーディングエージェント向けの機能は活発に更新されているため、フィードバックが重要です。最も簡単なのは、コーディングエージェントに直接頼む方法です。

セッション中に不審な挙動（エージェントが同じ処理をループしている、何度もリトライしている、CLI が想定どおり動かないなど）に気づいたら、その内容をエージェントに説明させ、フィードバック用のスキルを使ってもらってください。

```text
UiPath にフィードバックを送ってください: 〇〇に関する docsai の回答は、△△の点が説明されておらず不十分でした。
```

ターミナルから直接送ることもできます。

```bash
uip feedback send
```

- CLI を直接操作し、ヘルプとツール一覧を確認した
- `docsai` でドキュメントに問い合わせた
- 読み取り専用のコマンドでプラットフォームの情報を取得した
- 出力形式の使い分けを覚えた
- 問題を報告する方法を身につけた
