# 第1部の完了

!!! tip "おめでとうございます！"

    UiPath CLI とスキルをセットアップし、ターミナルからプラットフォームを操作し、最初のエージェントを構築・公開しました。

## 構築したもの

コーディングエージェントの実行環境が整いました。`uip` CLI がテナントに対して認証済みで、UiPath スキルがエージェントに読み込まれています。そのうえで、シンプルな Claims Eligibility エージェントを題材に **構築 → 公開 → 実行** のループを 1 周完了しました。

| コンポーネント | 役割 |
|-----------|------|
| **UiPath CLI**（`uip`） | コーディングエージェントがプラットフォームとやり取りするためのインターフェイス |
| **UiPath スキル** | CLI をいつ・どのように使うのかをエージェントに教える手順パック |
| **docsai** | ドキュメントに基づいて、UiPath に関する質問にターミナルから回答 |
| **最初のエージェント** | 自分で生成し、Studio Web に公開して実行したローコードエージェント |

## 次のステップ

### 1. 環境を最新に保つ

スキルとツールは活発に更新されています。ときどき更新してください。

```bash
uip skills update
uip tools update
```

### 2. 実用的なパイプラインを作る

シンプルなエージェントでループを 1 周しました。[**第2部 ローン審査の自動化**](../loan-application-underwriting/index.md) では、4 つのコンポーネントが連携する本格的なパイプラインを構築します。

- Python のコーデッドエージェント（ツールを持ち、外部 API を呼ぶ）
- React の Coded Action App（人が判断する画面）
- Maestro フロー（条件分岐と人的レビューのオーケストレーション）
- Studio の RPA ワークフロー（全体を駆動する）

## さらに磨きをかけるために

**コマンドではなく「やりたいこと」を伝える**

何をしてほしいかを説明し、コマンドの選択はエージェントに任せましょう。いまのうちにこの習慣を身につけてください。

**モデルを信頼する、ただし生成物は必ず読む**

序盤からトークンの最適化にこだわりすぎないようにしましょう。性能の高いモデルはミスが少ないため、結果的に安く済むことがよくあります。

一方で、**生成されたものを読まずに次へ進まないでください。** 第2部では、生成物のレビューを飛ばすと後のレッスンで詰まる箇所がいくつかあります。各レッスンの「確認するポイント」は、そのための節です。

**エラーが出たら `--help` を読ませる**

コマンドが失敗したとき、エージェントに推測させるより `--help` の出力を読ませるほうが速く正確です。

```text
そのコマンドの --help を実行して、使えるオプションを確認してから直してください。
```
