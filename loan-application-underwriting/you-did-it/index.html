    完了です！¶

    おめでとうございます！

    申込の受付から、AI による与信審査、人的レビュー、最終判断まで、Maestro がオーケストレーションするコードファーストなローン審査パイプラインを丸ごと構築しました。

    構築したもの¶

    4 つのコンポーネントが連携し、1 本の自動化パイプラインとして動作します。RPA ワークフローが申込者の CSV を読み込み、1 件ずつ UiBank に送信し、受理された申込ごとに Maestro Flow プロセスを開始します。フローの中では Python のエージェントが UiBank API を使って与信審査を行い、クレジットスコア、リスクバンド、審査サマリーを出力します。低リスクの申込は自動承認され、そこでフローは終了します。中・高リスクの申込ではフローが一時停止し、Action Center で React 製のダッシュボードが開きます。ローン担当者は AI の審査結果を確認して判断を送信します。フローはその判断を受け取り、最終結果を出力します。RPA 側に戻ると、結果が results.csv に書き込まれ、ストレージバケットにアップロードされます。

    コンポーネント 役割
    コーデッドエージェント（Python / LangGraph） loan_id を受け取り、3 つのツールで UiBank API を呼び出し、財務指標を計算し、LLM を使ってクレジットスコア・リスクバンド・審査サマリーを生成する
    Coded Action App（React / TypeScript） ローン担当者用ダッシュボード。Maestro から 12 個の入力すべてを受け取り、承認または却下の判断を受け付ける
    Maestro Flow エンドツーエンドのフローをオーケストレーションする。エージェントを呼び出し、リスクバンドで振り分け、人的レビュー用にアプリを開き、final_decision を出力する
    Studio RPA ワークフロー loan-applications.csv を読み込み、各行を UiBank に送信し、受理された申込ごとに Maestro Flow を開始し、results.csv を更新してストレージバケットにアップロードする

    いずれのコンポーネントも、UiPath スキルを使ってコーディングエージェントが生成し、uip CLI でデプロイしたものです。

    次のステップ¶

    1. エンドツーエンドで実際に実行してみる¶

    Orchestrator で CodingAgentsILT フォルダーを開きます。{YourName}LoanApplicationDispatcher を開いて実行を開始してください。RPA が申込を送信し、Maestro Flow を開始し、結果を返していく様子を確認できます。中・高リスクの申込については Action Center を開いて人的レビューのタスクを完了させてください。ローン担当者用ダッシュボードが、すべてのフィールドに値が入った状態で表示されるはずです。

    2. 結果を確認する¶

    一通り実行し終えたら results.csv を開きます。各行の最終ステータスが Loan Approved または Loan Rejected のいずれかになっているはずです。Orchestrator の Maestro 実行トレースと突き合わせ、振り分けがエージェントのリスクバンドと一致していたことを確認してください。

    さらに発展させるには¶

    与信ロジックを改善する

    現在は、LLM が 3 つの財務指標を総合的に解釈しています。市場平均に対する借入額の比率をより重視するようシステムプロンプトを調整したり、高収入の若年層と中程度の収入の年配層とを区別して扱うようにしてみてください。同じ 3 つのサンプルプロファイルで再テストし、リスクバンドがどう変わるかを観察しましょう。

    極端なケース向けに自動却下の経路を追加する

    現状では、中・高リスクの申込はすべてローン担当者に回されます。Maestro Flow に条件を追加し、credit_score < 20 の場合はその場で自動的に却下するようにしてみましょう。明らかなケースを除外でき、担当者のキューを減らせます。

    React アプリを拡張する

    3 つの財務指標を小さなチャートで表示するセクションをダッシュボードに追加してみましょう。DTI をバー、クレジットスコアをゲージ、市場平均に対する借入額の比率を比較線で示す、といった具合です。AI の推奨の裏側にある数値を、ローン担当者がより深く把握できるようになります。

    却下の経路を通知につなぐ

    却下が記録されたあと、申込者にメールを送る Integration Service のステップを追加してみましょう。Maestro Flow の却下終了状態のあとにノードを 1 つ足すだけ、コネクタの呼び出し 1 回で済みます。
